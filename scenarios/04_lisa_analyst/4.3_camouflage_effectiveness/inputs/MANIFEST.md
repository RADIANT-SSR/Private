# Input Manifest

Non-RADIANT scenario inputs. The vendor-form spectra and the sensor workbook are
generated by `create_spreadsheet.py`; `L_bare_vehicle.csv` is a committed golden
input described below.

| Input | Kind | Provenance |
|---|---|---|
| `create_spreadsheet.py` | generator script | authoritative source for the vendor-form inputs |
| `lisa_flir_sensor.xlsx` | sensor config (vendor units) | `create_spreadsheet.py` |
| `steel_oxidized_aster.txt` | ASTER emissivity export (bare vehicle) | `create_spreadsheet.py` |
| `camo_net_{a,b,c}.csv` | vendor emissivity spectra (nets A/B/C) | `create_spreadsheet.py` |
| `L_bare_vehicle.csv` | **committed golden input** — bare-vehicle at-source spectral radiance `L_t(λ) = ε(λ)·B(λ, 380 K)`, the S8 `user_radiance_path` the `.gui.yaml` baseline reloads | generated by `scripts/run_camouflage_analysis.py` (the `→ L_bare_vehicle.csv` step); committed per Rule 26(a) so the GUI baseline is portable in a cold checkout (CU-180). Regenerate by running the script; it is asserted against by `tests/integration/test_gui_baselines.py`. |

The other derived radiance CSVs (`L_camo_net_{a,b,c}.csv`, `L_scrub_background.csv`)
are regenerate-on-demand under `outputs/derived/` and are **not** committed — only
`L_bare_vehicle.csv` is a golden GUI-baseline input.

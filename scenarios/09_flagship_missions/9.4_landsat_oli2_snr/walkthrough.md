# 9.4 Landsat 9 OLI-2 — Nine-Band SNR at Typical Radiance, Per-Element Coated Optics

**Mission**: Landsat 9 OLI-2, 705 km SSO, 135 mm four-mirror off-axis anastigmat pushbroom
imager, 9 bands (VNIR Si PIN + SWIR HgCdTe on one 210 K FPA), 14-bit.
**Claims validated**: (1) RADIANT's aperture-to-electrons radiometry predicts the published
per-band SNR at L_typ; (2) a full **per-element prescription with synthetic coatings**
(first scenario to exercise Mode 5 end-to-end) reproduces the same result as a lumped
throughput, while exposing every optic's R/T/ε model individually; (3) all **nine** bands —
the pan band included — run as **one ADR-0010 configuration set** whose band filter is a
**configured element row** (Gap 103 v1.1).

## Design

Each band drives the chain with a flat user-radiance spectrum equal to the published
L_typ [W/m²/sr/µm] through a vacuum path (`atmosphere.model: exo`) — the requirement and
the on-orbit measurement are both stated at-aperture. Extended scene (EE_box = 1, the
regime OLI's per-detector uniform-scene SNR is defined in), no TDI, 3.6 ms integration
(30 m bands) / 1.8 ms (pan).

The optical train is **not** a `transmission_scalar`: it is six `optical_elements`
entries — M1–M4 (protected-silver reflectance curve, ε = 1−R Kirchhoff-derived per
Rule 5), an AR-coated FPA window, and the band's interference filter. **Every curve is
synthetic** — no per-surface curves are published for OLI — generated by
`scripts/gen_oli2_coatings.py` from vendor-typical anchors, with the filter 50% points
pinned to the published band edges. Provenance and recall-confidence classes for every
number: `docs/validation/landsat_oli2_source_data.md`.

**The all-bands study** (`oli2_all_bands_study.yaml`) is the headline artifact: nine
bands, one file. The shared instrument is stated **once** — aperture, focal length,
orbit, vacuum atmosphere, extended-scene machinery, readout chain, and element rows 0–4
(the four protected-Ag mirrors + the FPA window). What differs, and only what differs, is
configured:

| Configured surface | Per-band values |
|---|---|
| **Element row 5 — the band filter** (configured element row) | `filter_b01` … `filter_b09`, each entry complete: `data/filter_b0N.csv`, 210 K, 0.05 m, 0.005 m to FPA |
| `source.target.user_radiance_path` | `data/l_typ_b01.csv` … `l_typ_b09.csv` (flat L_typ = 40, 40, 30, 22, 14, 4.0, 1.7, 23, 6.0 W/m²/sr/µm) |
| `spectral_integration.filter_min_um` [µm] | 0.435, 0.452, 0.533, 0.636, 0.851, 1.566, 2.107, 0.503, 1.363 |
| `spectral_integration.filter_max_um` [µm] | 0.451, 0.512, 0.590, 0.673, 0.879, 1.651, 2.294, 0.676, 1.384 |
| `detector.qe_value` [-] | 0.70, 0.80, 0.85, 0.87, 0.78, 0.80, 0.75, 0.83, 0.80 |
| `detector.dark_rate_e_per_s` [e-/s] | 100, 100, 100, 100, 100, 5.0e4, 5.0e4, 100, 5.0e4 |
| `detector.pixel_pitch_x_um` / `_y_um` [µm] | 36 for the 30 m bands, **18** for B8_Pan |
| `spectral_integration.integration_time_s` [s] | 3.6e-3 for the 30 m bands, **1.8e-3** for B8_Pan |

The **configured element row** is what makes nine bands expressible in one file (Gap 103
v1.1, owner-ratified 2026-09-02): row 5 of the shared `optical_elements` document carries
one *complete* entry per configuration — dense, name included — exactly as a configured
parameter carries one value per configuration. Each band therefore mounts its own
synthesized interference strip, which is what the real butcher-block assembly does
*spatially* (different detector rows behind different strips). The panchromatic band,
whose filter overlaps green and red and whose pitch and line time differ, is an ordinary
member of the study: its 18 µm pitch and 1.8 ms line time are ordinary configured
scalars, and its filter is just its entry on the configured row.

The nine per-band files (`oli2_b0N_snr_ltyp.yaml`) remain as the **cross-checks**: each
is the same model written out standalone, and `scripts/check_all_bands_parity.py` asserts
that the study reproduces every one of them (below).

## Run

From this folder:

```bash
radiant validate oli2_all_bands_study.yaml               # all 9 configurations
radiant run oli2_all_bands_study.yaml --configuration B5_NIR
radiant run oli2_b05_snr_ltyp.yaml                       # the same band, standalone
python scripts/check_all_bands_parity.py                 # study vs. all nine standalones
```

or open `oli2_all_bands_study.yaml` in the GUI (`radiant gui oli2_all_bands_study.yaml`;
see `gui_workflow.md` for the per-configuration Elements walkthrough).

## Expected results (chain central values vs published)

| Band | RADIANT SNR [-] | Required [-] [Irons 2012] | L8 measured [-] (recalled ±15%) [Morfitt 2015] | Prediction / measured |
|---|---|---|---|---|
| B1 CA | 177 | ≥130 | ~230 | 0.77 |
| B2 Blue | 496 | ≥130 | ~360 | 1.38 |
| B3 Green | 472 | ≥100 | ~300 | 1.57 |
| B4 Red | 341 | ≥90 | ~225 | 1.51 |
| B5 NIR | 238 | ≥90 | ~200 | 1.19 |
| B6 SWIR1 | 328 | ≥100 | ~265 | 1.24 |
| B7 SWIR2 | 367 | ≥100 | ~180 | 2.04 |
| B8 Pan | 227 | ≥80 | ~145 | 1.56 |
| B9 Cirrus | 139 | ≥50 | ~165 | 0.84 |

Signals run 39.5 ke- (B9) to 282 ke- (B2); shot-noise-dominated in every band (read
noise 200 e- RMS is ≤6% of total noise; dark ≤180 e-/frame even for SWIR).

**Verdict: CONSISTENT.** Every prediction clears the requirement; the ratio to flight
sits in the 0.8–2.0× envelope the 9.1 dossier established for assumption-class QE·τ.
Central predictions land *above* flight where band-average QE and filter peak are
generous, because RADIANT models no PRNU, striping, or calibration-transfer noise.
B1 and B9 land *below* the recalled flight values: both are narrow bands (16 nm /
21 nm) where the band-edge roll-off of the synthetic super-Gaussian filter eats a
larger fraction of the integral and the assumed QE (0.70 at 443 nm; 0.80 for 1.37 µm
MCT) is deliberately conservative — the flight instrument evidently does better. The
recalled measured values themselves carry ±15% (see gaps.md: verification pass).

**Study vs standalone equivalence — exact.** `scripts/check_all_bands_parity.py`
evaluates all nine configurations and all nine standalone files and compares SNR:

Every band is bit-identical — far inside the `rel < 1e-9` acceptance bar. This is
expected *by construction*, not a coincidence: materializing configuration N
(`ConfigurationSet.sensor_for`) reproduces standalone N's effective document field for
field — same band edges, hence the same 500-point grid over the same span; same filter
CSV on row 5; same QE, dark rate, pitch and integration time — so the two runs drive the
same deterministic chain. (Historically B1/B2 differed by ≤0.5% because the study shared
one *composite* filter element whose union carried both strips' roll-off across the
1 nm B1/B2 seam. With per-band filter entries that artifact is gone, and the study now
carries the faithful value at the seam.)

## Physics notes (read before editing)

- **Regime**: extended in every configuration — EE_box is not applied (Rule 9), and the
  (ε, T) target doors are unused: the source term is the user-radiance table alone.
- **Thermal self-emission of the train is modeled and non-binding**: elements carry
  Kirchhoff ε at 293 K (mirrors) / 240 K (window) / 210 K (filter); at λ ≤ 2.3 µm these
  emit orders of magnitude below L_typ. Deleting the temperatures changes nothing
  visible — they are there because Mode 5 models them, not because they matter here.
- **Unused parameter groups**: platform jitter/smear defaults are untouched (SNR at
  L_typ is a radiometric claim; the spatial path runs at defaults), and
  `gain_e_per_dn`/`full_well_capacity_e` are analysis-mode values — saturation is out
  of scope (see gaps.md).
- **End-to-end throughput** (B4 band-average): 0.975⁴ (four Ag mirrors) × 0.985
  (window) × 0.90 (filter peak) ≈ 0.80 [-]; inspect per-element curves via the GUI
  coating-detail pane or `plots.coating_spectra()`.
- **Row structure is shared, row content may be configured**: every configuration has the
  same six rows in the same order (positional identity). A configuration cannot add or
  remove an element — that remains out of scope by design.

Non-RADIANT inputs: everything under `data/` (21 CSVs) — regenerated byte-identically by
`python scripts/gen_oli2_coatings.py` (Rule 26 manifest in that script's docstring).
`data/filter_butcher_block.csv` is the D-7-era composite: no config file uses it now that
each band carries its own strip, and the generator still emits it as a documented
historical artifact.
